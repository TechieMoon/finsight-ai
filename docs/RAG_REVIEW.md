# RAG 결과 검토 (2026-10-31)

## 검토 대상과 방법

2026-10-29 Baseline에서 실제 데이터로 실행한 RAG 질문 24개의 저장 결과(`evaluation/baseline/2026-10-29/rag-results.json`)를 다시 살펴봤습니다. 검색된 후보 청크와 최종 채택된 인용을 읽고 질문에 실제로 답하는지 판단했습니다. 이 검토는 Codex가 일부 사례에 대해 정성적으로 진행한 것입니다. 사람이 정답 근거를 확정한 것은 아니며, `rag-reviews.json`의 검토 상태와 지표는 바꾸지 않았습니다.

## 주요 사례

| 사례 | 관찰 | 더 확인할 것 |
|---|---|---|
| R03 AI 서버 수요와 실적 | 채택된 청크 385는 2024년 AI 서버·고성능 메모리 수요와 업황 개선, 당기 실적을 함께 설명합니다. 질문을 뒷받침하는 근거로 볼 만합니다. | 수요가 실적에 준 효과를 금액으로 보여 주는 근거는 아닙니다. 원문 전체를 보고 사람이 판단해야 합니다. |
| R08 고부가 제품과 수익성 | 채택된 청크 490은 보수·성과급 산정 문맥에서 시작하고 "2024년 Turn-around 기반"을 언급합니다. 보고서 연도만 보고 이 설명을 당기 성과로 단정할 수 없습니다. | 앞 청크와 원문에서 어느 연도 성과인지 확인한 뒤 채택 여부를 정해야 합니다. |
| R09 가격과 실적 | 채택된 인용 4개는 AI 수요, 매출·이익, HBM 경쟁력과 판매 확대를 설명합니다. 가격 변화가 실적에 준 영향을 직접 설명하는 문장은 부족합니다. | 관련은 있지만 질문에 직접 답하지 않는 문장을 구분해야 합니다. |
| R01 일반적인 실적 원인 | 검색 후보 385에 당기 개요가 있지만 최종 인용은 비어 있습니다. | 검색 실패인지 인용 선택 누락인지 나눠 봐야 합니다. |
| R13 HBM 이익 기여 비율 | 비율을 지어내지 않고 근거가 부족하다고 안내했습니다. | 원문 전체에 해당 비율이 정말 없는지는 아직 확인하지 않았습니다. |
| R21 수집하지 않은 기업 | 삼성전자 공시를 색인하지 않은 상태라 근거 없음 경고가 나왔습니다. | 검색할 문서가 없는 경우와 공시에 내용이 없는 경우를 같은 것으로 보지 않습니다. |

채택된 인용 6개 가운데 R03의 1개는 질문을 뒷받침하는 후보, R08의 1개는 귀속 연도 확인이 필요, R09의 4개는 가격 질문에 대한 직접 근거가 부족하다고 봤습니다. 표본이 작고 사람의 정답이 없어서 정밀도나 Recall은 계산하지 않았습니다.

R03과 R09는 전년 비교를 묻지 않은 당기 원인 질문이라 2024년 데이터만 조회했고, 그래서 증가율이 나오지 않았습니다. 현재 규칙대로의 동작입니다. SK하이닉스의 2024년 영업이익은 전년 적자에서 흑자로 돌아선 경우라 전년을 조회해도 일반 증가율 대신 흑자 전환으로 표시합니다.

## XML 수정 후 다시 실행한 결과

XML 정제 오류를 고친 뒤([XML 수정 기록](XML_REPAIR.md)) 새로 만든 임시 색인(833개 청크)에서 R03, R09, R13을 실제 DART·OpenAI로 다시 실행했습니다. 세 질문 모두 정상 완료됐고 채택 인용은 각각 1개, 3개, 0개였습니다. R09는 여전히 제품 구성·판매 설명과 가격 변화의 효과를 구분하지 못합니다. 결과는 `evaluation/xml-repair-2026-10-31/targeted-rag.json`에 있고, 기존 24문항 결과는 덮어쓰지 않았습니다.

## 그 밖에 고친 것

- 값이 없는 비율이 `산출 불가%`로 표시되던 문제를 `산출 불가`로 고치고 회귀 테스트를 추가했습니다.
- UI 테스트의 첫 import가 기본 3초 제한을 넘겨 실패해서, smoke 검사와 같은 30초 제한을 적용했습니다.
- 브라우저에서 비교 질문을 실행했을 때 Vega 차트의 extent/scale 경고가 콘솔에 남지만 차트는 정상적으로 표시됩니다.
