# 한계와 개선 순서

## 현재 검증과 잔여 과제

1. 두 기업 2023~2025 CFS 원문 대조는 기존 Baseline에서 수행했습니다. OFS 실제 대조와 회계정책 비교 가능성 검토는 남아 있습니다.
2. XML 정제 회귀를 수정해 보관 원본 24개와 실제 SK하이닉스 2024 수집·임베딩·검색 검사를 통과했습니다. 다른 기업·문서 형식과 최신 정정 원문 링크 대조는 확대 검증이 필요합니다.
3. 기존 원문 대조 12/12와 계산 가능한 비율 17/17은 자동 일치 검사이며 사람의 회계 검토가 아닙니다.
4. 실제 RAG 24문항 실행 기록이 있습니다. 질문별 관련 청크 정답 집합과 인용 적합성은 사람이 검토해야 합니다.
5. 실제 문서에 대한 검색 회수·근거 적합성과 잘못된 원인 설명 여부 평가.
6. Python 3.11 및 배포 대상 OS에서 동일 테스트 수행.

수정·재검증 결과는 [XML 수정 기록](XML_REPAIR.md), 의미적 한계 사례는 [제출 준비 검토](SUBMISSION_REVIEW.md)에 구분했습니다.

## 현재 알려진 기능 제약

- 2개 기업, 연간 매출·영업이익에 한정. 분기, 현금흐름, 주가, 전망, 투자 추천 미지원.
- 단일 질문 처리. 이전 질문의 기업·연도를 기억하지 않는다. '두 기업'은 지원 기업 2곳을 뜻한다.
- 규칙 기반 라우팅은 복잡한 표현·범위 밖 지표·다중 의도를 완전히 탐지하지 못할 수 있다.
- 회계정책 변경·사업구조 변경·재작성 전후의 경제적 비교 가능성은 자동 판정하지 않는다.
- 12월 결산 전제이며 전체 재무제표 응답에 날짜가 없으면 기간은 전제로 구성한다.
- 공시 텍스트 청크는 표 구조/장 제목을 보존하지 않으며 파일 전체에 관련 없는 내용이 많을 수 있다.
- RAG는 수집된 공시만 조회한다. 일일 자동 갱신과 수집 재개/트랜잭션 기능은 없다.
- 최신 정정본 갱신 중 장애가 나면 일부 청크만 저장될 수 있다. 같은 수집 명령으로 복구한다.
- 최종 공시 답변은 원문 발췌이며 매끄러운 종합 요약보다 근거 검증을 우선한다.
- 실제 API·임베딩·검색 연동은 검사했으나 의미 검색 품질의 사람 정답 평가는 미완료입니다. Mock 성공 수치를 실제 정확도로 사용하지 않습니다.
- 공개 서비스용 인증·영속 다중 인스턴스 쿼터·로그 모니터링이 없다.

## P1 — P0 실제 검증 통과 후

Dockerfile/Compose, Python 3.11 CI, 비밀키 주입형 클라우드 배포, 수동 정답 기반 RAG 개선.
배포·GitHub push는 사용자 승인 후 진행한다. MCP는 기존 도구 인터페이스 재사용 가치가 있을 때 추가한다.

## P2 — 제출 이후

대화 이력, 재무 항목 확대, 문서 구조 기반 청킹, 하이브리드 검색/재순위화,
공시 갱신 잡, 추적/관측성, 정정 공시 시점별 데이터 버전 관리.
Multi-Agent는 독립적으로 병렬 처리해야 하는 분석 역할이 생겼을 때만 재평가한다.
