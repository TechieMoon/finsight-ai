# 한계와 다음 단계

## 아직 검증하지 못한 것

1. 두 기업 2023~2025년 연결(CFS) 수치는 원문과 대조했지만, 별도(OFS) 수치의 실제 대조와 회계정책 비교 가능성 검토는 하지 않았습니다.
2. XML 정제는 보관한 원본 24개와 SK하이닉스 2024년 수집·임베딩·검색으로 확인했습니다. 다른 기업·문서 형식과 최신 정정 공시까지는 확인하지 않았습니다.
3. 원문 대조 12/12와 비율 17/17은 자동 대조 결과이며, 사람이 회계 검토를 한 것은 아닙니다.
4. 실제 RAG 질문 24개의 실행 기록은 있지만, 질문별 정답 청크와 인용의 적합성은 사람이 판단해야 합니다.
5. 검색이 관련 근거를 얼마나 찾는지, 잘못된 원인 설명을 내놓지 않는지는 아직 평가하지 않았습니다.
6. Python 3.11과 배포 대상 OS에서는 테스트를 돌려 보지 않았습니다.

수정 결과는 [XML 수정 기록](XML_REPAIR.md), 사례별 의미상 한계는 [RAG 결과 검토](RAG_REVIEW.md)에 있습니다.

## 기능 제약

- 2개 기업의 연간 매출·영업이익만 다룹니다. 분기, 현금흐름, 주가, 전망, 투자 추천은 지원하지 않습니다.
- 질문 하나씩 처리합니다. 이전 질문의 기업·연도를 기억하지 않으며, '두 기업'은 지원하는 두 회사를 뜻합니다.
- 규칙 기반 라우팅이라 복잡한 표현, 범위 밖 지표, 여러 의도가 섞인 질문을 모두 잡아내지는 못합니다.
- 회계정책 변경, 사업구조 변경, 재작성 전후의 비교 가능성은 판단하지 않습니다.
- 12월 결산을 전제로 하며, 재무제표 응답에 날짜가 없으면 그 전제로 기간을 구성합니다.
- 공시 청크는 표 구조와 장 제목을 보존하지 않습니다.
- 수집한 공시만 검색합니다. 자동 갱신, 수집 재개, 트랜잭션 처리는 없습니다.
- 정정 공시로 갱신하는 도중 오류가 나면 일부 청크만 저장될 수 있습니다. 같은 수집 명령을 다시 실행하면 복구됩니다.
- 공시 답변은 원문 발췌라서 매끄러운 요약보다는 근거 확인이 쉬운 쪽을 택했습니다.
- 공개 서비스에 필요한 인증, 다중 인스턴스 호출 한도, 로그 모니터링은 없습니다.

**그 이후:** 대화 이력, 재무 항목 확대, 문서 구조 기반 청킹, 하이브리드 검색과 재순위화, 공시 자동 갱신, 추적·관측성, 정정 공시 시점별 데이터 버전 관리. Multi-Agent는 독립적으로 병렬 처리할 분석 역할이 생길 때 다시 검토합니다.
