# 제출 준비 검토 2026년 10월 31일

## 초기 준비 단계의 과거 실행

원본과 키가 전달되기 전 Windows Python 3.12.14의 새 가상환경에서 회귀 테스트 **69 passed, 2 skipped**, Ruff 검사를 통과했습니다. Mock 질문 평가도 **24/24** 통과했습니다. 실제 공급자 테스트 2개는 키가 없어 실행하지 않았습니다. 이 결과는 실제 수집 오류 해결이나 금융 답변 정확도 검증을 뜻하지 않습니다.

FastAPI와 Streamlit을 별도 프로세스로 실행하고 브라우저에서 기본 비교 질문을 제출했습니다. 합성 재무 6행, 비교표, 매출·영업이익 차트와 출처 표시를 확인했습니다. 브라우저에는 Vega 차트의 extent/scale 경고가 남지만 결과 차트는 표시됐습니다. 부하·지연 시간은 측정하지 않았습니다.

`산출 불가%`로 표시되던 비율 문구를 `산출 불가`로 수정했습니다. 값이 없는 비율에 퍼센트 기호를 붙이지 않도록 회귀 검사를 추가했습니다. UI 테스트의 첫 import가 기본 3초 제한을 넘겨 실패해, 기존 smoke 검사와 같은 30초 실행 제한을 적용했습니다.

화면 파일은 `docs/screenshots/`에 있으며 **MOCK 합성 데이터**임을 명확히 표시합니다. 실제 데이터 성과는 2026-10-29 Baseline의 원본 기록으로 별도 확인해야 합니다.

## 기존 RAG 결과의 주요 사례

검토 대상은 `evaluation/baseline/2026-10-29/rag-results.json`의 저장된 검색 후보와 채택 인용입니다. 아래 내용은 **Codex의 부분 정성 검토**이며, 사람의 gold 판정이나 새 RAG 실행 결과가 아닙니다. 기존 `rag-reviews.json`의 사람 검토 상태와 정량 지표는 변경하지 않았습니다.

| 사례 | 관측과 판단 | 다음 확인 |
|---|---|---|
| R03 AI 서버 수요와 실적 | 채택 청크 385는 2024년 AI 서버·고성능 메모리 수요, 업황 개선과 당기 실적을 함께 설명합니다. 질문을 정성적으로 뒷받침하는 후보입니다. | 수요 효과의 금액·독립 인과관계를 계산한 근거는 아닙니다. 전체 원문과 사람 검토 필요 |
| R08 고부가 제품과 수익성 | 채택 청크 490은 보수·성과급 산정 문맥에서 시작하고 “2024년 Turn-around 기반”을 언급합니다. 보고서 기준연도만으로 그 안의 실적 설명을 당기 성과로 확정할 수 없습니다. | 바로 앞 청크와 원문에서 성과 귀속 연도를 확인한 뒤 채택 여부 결정 |
| R09 가격과 실적 | 채택 인용 4개는 AI 수요, 매출·이익, HBM 경쟁력과 판매 확대를 설명합니다. 가격 변화가 실적에 미친 영향을 직접 설명하는 근거는 부족합니다. | 관련성이 있는 문장과 질문에 직접 답하는 문장을 구분 |
| R01 일반적인 실적 원인 | 검색 후보 385에 당기 개요 설명이 있지만 최종 인용은 비어 있습니다. | 검색 실패와 인용 선택 누락을 분리해 검토 |
| R13 HBM 이익 기여 비율 | 정확한 비율을 생성하지 않고 근거 부족을 안내했습니다. | 전체 원문에 해당 비율이 없는지는 아직 확정하지 않음 |
| R21 미수집 기업 대조군 | 삼성전자 공시가 색인되지 않은 조건에서 근거 없음 경고가 나왔습니다. | 검색 불가와 원문 미공시를 동일하게 판단하지 않음 |

6개 채택 인용 중 R03의 1개는 정성적 지원 후보, R08의 1개는 귀속 연도 추가 확인 필요, R09의 4개는 가격 질문에 대한 직접 근거 부족으로 보았습니다. 이 분류로 정밀도·Recall·거부 정확도를 계산하지 않습니다.

## XML 수정과 실제 연동 재검증 완료

원본 data 폴더와 등록된 환경변수 키를 전달받은 뒤 XML 정제 회귀를 수정했습니다. 2026-10-29 원본 해시 24/24 일치를 확인했고, 24개 XML 모두 정제를 통과했습니다. 이스케이프되지 않은 &와 확인된 본문 꺾쇠 표기를 처리하되, 깨진 태그·DTD·외부 엔티티·잘못된 참조의 거부는 유지합니다.

수정 후 로컬 테스트는 **76 passed, 2 skipped**, Ruff 통과입니다. 기존 실제 연동 검사 두 개를 별도로 실행해 **재무 조회와 실제 공시 수집·OpenAI 임베딩·Chroma 검색 모두 통과**했습니다. 임시 저장소를 사용해 기존 생산·Baseline DB를 보존했습니다. 자세한 원인과 범위는 [XML 수정 기록](XML_REPAIR.md)에 있습니다.

기존 RAG 정성 검토와 사람 정답 미확정 상태는 위와 같습니다. XML 수정이나 검색 결과 존재만으로 의미적 정확도 향상을 주장하지 않습니다. MCP와 배포는 이번 제출 준비 범위에 추가하지 않았습니다.

추가로 새 임시 색인 833개 청크에서 R03·R09·R13을 실제 DART/OpenAI로 실행했습니다. 세 질문 모두 실행 완료했고 인용은 1·3·0개였습니다. R09는 제품 구성·판매 설명과 가격 변화의 효과를 구분하는 과제가 남았습니다. 세부 결과는 `evaluation/xml-repair-2026-10-31/targeted-rag.json`에 저장했습니다. 기존 24문항 결과나 사람 정답 상태는 덮어쓰지 않았습니다.

## 최종 제출 정리

지원자는 요구사항 정의·설계 방향 결정·Codex 구현 지시·테스트 기준 검토 및 결과 확인을 담당했습니다. 코드 작성과 자동 테스트·실제 API 검사 실행은 Codex가 수행했습니다. 76개 오프라인 통과와 별도 실제 검사 2개를 구분하며, 사람의 RAG 의미 정확도 검증은 완료하지 않았습니다. 실제 검사 2개는 별도 프로세스에서 기존 테스트 함수를 직접 호출한 결과이며 pytest 통과 수에 합산하지 않습니다.

R03/R09는 전년 비교를 명시하지 않은 당기 원인 질문이므로 2024년 데이터만 조회했습니다. 증가율에 필요한 2023년 값이 없어 미산출된 것은 현재 규칙에 따른 동작입니다. SK하이닉스의 2024년 영업이익은 전기 적자에서 흑자 전환으로, 전년을 조회해도 일반 증가율을 산출하지 않습니다. R13은 실제 브라우저 화면에서도 근거 부족 안내가 표시됐으며, 이익 기여 비율을 만들어내지 않았습니다.

최종 공개 기록은 환경 식별 정보를 제거한 사본입니다. 로컬 원본·DB·중간 실패 실험 및 개인정보가 있는 제출 문서는 공개하지 않습니다.
